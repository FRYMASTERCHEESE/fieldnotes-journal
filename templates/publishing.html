FIELDNOTES / PUBLISHING GUIDE

Original stories.
Shared responsibly.

For approved authors

Open the Author Studio, write your headline, introduction and article, then choose a cover. Reading time, preview, formatting, submission data and a Facebook caption are prepared automatically. Save a local draft or download a backup while you work.

Prepare editor review opens a public GitHub submission for you to check and submit. You need a GitHub account. The automation checks your username against the editor’s approved author list. Approved submissions prepare a draft branch and an editor review link. A review request is opened automatically where repository settings permit it; otherwise the editor opens the prepared link. The editor reviews the article and image rights before merging it for publication. Unapproved users cannot publish through the submission automation.

For the editor

Only the repository owner currently has publishing access. Add approved GitHub usernames and display names in authors.json; authors do not need write access to the repository. Keep repository write access restricted to editors. Review the factual claims, originality, image permissions, credits and alt text in each review request. An approval list is an editorial control, not proof that someone owns the submitted material.

Merge an approved review request to publish. Build, accessibility and browser checks run before deployment, then again on the live site. A failed build blocks deployment. For submissions prepared by the automation, run Test and publish journal on the draft branch before merging if you want browser checks before approval.

Activate topic-to-article generation

Generation is built but is inactive until the owner configures an API credential. Add an OpenAI API key as a repository Actions secret named OPENAI_API_KEY in GitHub Actions secrets. Do not put the key in a draft, issue, source file or browser field. Then run Test and publish journal on main to refresh the studio’s activation status. An API project with billing and access to the configured text and image models is required.

In the Author Studio, enter a topic, optional angle and verified notes, choose a section and tone, then prepare a generation request. Review it on GitHub and click Create. Approved authors receive an editable article, original AI cover, Facebook caption and review notes through a link in the issue comments. No article is published at this stage.

Open that review link, edit the draft, check the facts and illustration, and tick the editorial confirmation. Prepare approval to publish opens a GitHub approval request. Only the repository owner can submit an accepted approval. That explicit approval commits the reviewed article and queues the build, browser tests and deployment. If checks fail, the site is not deployed; correct the source or rerun the workflow after resolving the failure. Facebook sharing stays manual.

Each request generates approximately 600 words and one image. The default limit is three approved-author topic requests per UTC day; requests with no credential never call the AI service. A paid request is attempted once, with no automatic paid retry. Adjust model names and request limits in generation.json, and configure your own API billing controls. The generator does not browse or verify current news, and its output is not a copyright guarantee. Generated images are labelled as illustrations. Facts, quotations, source notes, originality and image suitability remain your review responsibility.

Images you can publish

Use your own photographs, work you have written permission to publish and promote, or material whose licence explicitly covers your intended use. “Found online” or “free download” is not evidence of permission. Attribution alone does not replace permission. Read the IPONZ guide to getting permission.

Custom cover images use a public GitHub attachment URL. Record the photographer, source, licence or written permission, and a useful image description. The studio can prepare a 1200 × 630 JPEG from a local image for Facebook; inspect the crop before using it. Retain your original file and permission records.

The supplied coastal artwork was created with AI for this journal and is labelled as an illustration. It is not documentary evidence of a real place or event. AI-generated artwork is not a guarantee of copyright clearance; the editor must still check it for inappropriate likenesses, trademarks and other concerns.

Sharing on Facebook

After the article is live, use its Share on Facebook button to open Facebook’s share dialog, or Copy Facebook caption to copy the headline, introduction and link. You choose the audience and submit the post yourself. The site never posts automatically. Facebook controls how and when its link preview updates.

Our design and editorial promise

This site uses an original editorial design. It is independent and is not affiliated with the NZ Herald. Do not submit copied newspaper stories, branding or photographs without permission. Rewrite from your own research, verify facts, cite sources where appropriate, and distinguish opinion and illustration from reporting.

Corrections and rights concerns

Use the contact page to report a correction or rights concern. Include the article URL and enough public information for the editor to investigate. Do not post private personal information in public GitHub issues.
